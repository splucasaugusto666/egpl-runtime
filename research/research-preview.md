# Evidence-gated prompt contracts: a research proposal

Status: unreviewed research preview. 2026-11-24. No real-model experimental results.

## Abstract
We investigate whether bounded prompt adaptation with host-controlled completion predicates can reduce false completion without unacceptable overhead. A minimal reference implementation isolates candidate generation from an exact-match predicate. Synthetic fixtures demonstrate enforcement under the trusted-host assumption; they do not establish a new paradigm or model superiority.

## Related work and novelty audit
Preliminary source scan, not a systematic review. ReAct (Yao et al., 2022/2023, https://arxiv.org/abs/2210.03629) interleaves reasoning and actions; its task results are not directly comparable with our fixtures. DSPy (Khattab et al., 2023/2024, https://arxiv.org/abs/2310.03714) compiles declarative LM pipelines against metrics. DSPy Assertions (Singhvi et al., 2023, https://arxiv.org/abs/2312.13382) is especially close: computational constraints and inference-time refinement; it rules out a broad novelty claim for constrained prompt loops. Self-Refine (Madaan et al., 2023, https://arxiv.org/abs/2303.17651) uses iterative feedback; Promptbreeder (Fernando et al., 2024, https://proceedings.mlr.press/v235/fernando24a.html) evolves prompts and mutation prompts. TextGrad (Yuksekgonul et al., 2024, https://arxiv.org/abs/2406.07496) optimizes text variables with textual feedback. AgentSpec (Wang et al., https://arxiv.org/abs/2503.18666) enforces runtime constraints. Open Agent Specification (https://doi.org/10.1145/3786335.3813130) provides a common workflow representation and cross-runtime comparisons. More recent related preprints to examine include SKILL.nb (https://arxiv.org/abs/2606.08049), Proof of Execution (https://arxiv.org/abs/2607.05397), and AgentEval (https://arxiv.org/abs/2610.21177). The latter three were identified in an initial abstract search; full-paper audit remains pending. Do not infer lack of overlap from this list. Prior studies have different task distributions, models, evaluators and threat assumptions.

## Candidate architectures
A. Evidence-gated contract FSM: host-owned invariants and predicate; model supplies candidates; retry only within budget. Strength: small auditable core. Weakness: predicate design and limited generality.
B. Counterexample-guided prompt synthesis: a verifier produces counterexamples and a synthesizer revises strategy on development tasks. Strength: learns recurring failures. Weakness: evaluation leakage and expensive search.
C. Evidence dependency graph: actions produce typed artifacts and completion requires satisfaction of a graph of obligations; invalidate descendants if evidence changes. Strength: multi-step reasoning and provenance. Weakness: complexity and state explosion.
Select A for the first executable reference. B and C remain research candidates. Novelty is unproven; the candidate differentiator is a minimal portable boundary between mutable strategies, immutable obligations and completion evidence, not the invention of verification.

## Hypotheses and experimental methodology
H1: at equal cost, externally gated completion reduces false accepts on tasks with independent predicates. H0: no improvement, or overhead outweighs benefit. H2: invariant-preserving adaptation improves quality/cost on held-out tasks compared with fixed strategies. Pre-register datasets and scoring before running. Compare one-shot, fixed-budget retries without gate, gate without adaptation, gate with adaptation, and DSPy Assertions under identical model versions, tool capabilities and budgets. Separate dev/test sets. Measure correctness, false acceptance, false rejection, calls, tokens, latency, costs and recovery. Report paired intervals and negative results. Test multi-provider behavior only after actual integration. No performance claims are justified yet.

## Initial results
Eight handcrafted fault cases: one-shot accepted six wrong candidates and one correct candidate; gated runtime verified four cases with zero incorrect acceptances and twelve recorded attempts. Four cases remain unresolved; exact statuses in JSON. This is an intentionally easy deterministic predicate and a weak baseline, not an equal-budget model benchmark. The result is expected from the implementation. Unit tests exercise the boundedness and predicate rules; no formal proof or independent replication is claimed.

## Limitations and future work
No LLM calls, no live tool actions, no independent verification service, no adversarial sandbox, no token/time enforcement, no systematic novelty audit. Checkpoints replay candidate predicates but are not authenticated. Add richer typed predicates, disjoint benchmark data, realistic tool adapters, external evidence provenance, signed checkpoints where necessary, budget enforcement and pre-registered comparisons. Revisit the architecture if existing systems already offer equal or superior functionality.
